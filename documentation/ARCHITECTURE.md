# Архитектура проекта

## Общая идея

Проект `mosobr_ai` — это локальный AI-помощник по колледжам Москвы.

Он не обучает модель заново. Вместо этого используется подход RAG:

1. Данные о колледжах и FAQ загружаются из JSON.
2. Из данных собираются документы для поиска.
3. Для документов считаются embeddings.
4. При вопросе пользователя система ищет релевантные документы.
5. Локальная LLM получает найденные факты и формирует ответ.

---

## Основной pipeline

```text
Пользователь
↓
Telegram / API / CLI
↓
ChatService
↓
DialogRouter
↓
Retriever
↓
Ollama / Qwen
↓
Ответ пользователю
```

---

## Основные компоненты

### `app/interfaces/telegram_bot.py`

Telegram-интерфейс.

Отвечает за:
- команду `/start`;
- кнопку начала диалога;
- кнопку завершения сессии;
- передачу сообщений в `TelegramChatAdapter`.

---

### `app/interfaces/tg_adapter.py`

Адаптер между Telegram и ядром проекта.

Отвечает за:
- вызов `ChatService`;
- форматирование ответов под Telegram;
- сохранение текстовых логов диалогов.

---

### `app/interfaces/api.py`

HTTP API на FastAPI.

Используется для:
- подключения сайта;
- демонстрации web-чата;
- выгрузки логов;
- проверки работоспособности сервиса.

Основные endpoints:
- `GET /api/health`
- `POST /api/chat`
- `POST /api/session/close`
- `POST /api/session/reset`
- `GET /api/demo`
- `GET /api/logs/list`
- `GET /api/logs/download`

---

### `app/services/chat_service.py`

Главная логика диалога.

Отвечает за:
- создание/получение сессии;
- обработку запроса пользователя;
- вызов router;
- вызов retriever;
- выбор типа ответа;
- fallback-ответы;
- защиту от галлюцинаций;
- обработку FAQ, профориентации и уточнений.

---

### `app/services/dialog_router.py`

Маршрутизатор диалога.

Он определяет режим работы:

```text
script
recommend_colleges
faq
chat
detail
detail_more
career_guidance
out_of_scope
```

Примеры:
- `script` — приветствие, кто ты, оскорбления, источник данных;
- `faq` — документы, ОВЗ, армия, поступление;
- `detail` — рассказ про конкретный колледж;
- `detail_more` — все специальности, подробнее, продолжение темы;
- `career_guidance` — профориентация;
- `recommend_colleges` — подбор колледжей;
- `out_of_scope` — темы вне задачи проекта.

---

### `app/rag/retriever.py`

Поиск релевантных документов.

Использует:
- embedding similarity;
- keyword score;
- domain score;
- специальные правила для колледжей и направлений.

Важно: retriever не должен сам отвечать пользователю. Он только выбирает документы.

---

### `app/rag/embedder.py`

Загрузка embedding-модели и кодирование текста.

Используемая модель:

```text
BAAI/bge-m3
```

Она нужна для смыслового поиска по базе документов.

---

### `app/llm/ollama_client.py`

Клиент для Ollama.

Отправляет prompt в локальную LLM и возвращает текст ответа.

---

### `app/services/session_service.py`

Работа с сессиями и историей диалога.

Сессии нужны, чтобы бот понимал продолжения:
- “расскажи подробнее”;
- “а какие ещё?”;
- “про третью специальность”;
- “объясни проще”.

---

### `app/ingest/`

Модуль загрузки данных.

Этапы:
1. загрузка JSON;
2. нормализация;
3. сборка документов;
4. генерация embeddings;
5. запись документов в PostgreSQL.

---

## База данных

Используется PostgreSQL.

Основные данные:
- документы колледжей;
- документы специальностей;
- FAQ;
- сессии пользователей;
- история сообщений.

---

## Почему RAG

RAG выбран потому что:
- модель не нужно дообучать;
- данные можно обновлять через JSON;
- ответы опираются на факты из базы;
- систему можно запускать локально.

---

## Ограничения

Система не гарантирует абсолютную актуальность правил приёма. Пользователю рекомендуется перепроверять информацию:
- на сайте колледжа;
- в приёмной комиссии;
- в Атласе профессий;
- на сайте Центра профессий будущего.
